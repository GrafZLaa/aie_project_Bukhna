# ПАСПОРТ.ЦИФ — итоговый проект по курсу «Инженерия Искусственного Интеллекта»

Веб-сервис для автономного извлечения структурированных данных из PDF и
сканов паспортов промышленного оборудования. Связка **OCR (Tesseract) +
правила (regex) + опциональная мультимодальная LLM (Ollama)**. Результат —
очищенный JSON по полям + Excel-выгрузка под загрузку в учётные системы (1С).

Проект изначально сделан на хакатоне и в этом репозитории переоформлен
под структуру курса.

- **Название:** ПАСПОРТ.ЦИФ — автоматизация обработки паспортов оборудования
- **Автор:** Бухна Денис
- **Контакт:** denisprotopsuper@gmail.com
- **Преподаватель (согласование темы):** Юрий Владимирович
- **Краткое описание:**
  > Сервис принимает PDF/изображения паспортов оборудования (одиночных,
  > групповых, перечни шкафа), рендерит страницы, прогоняет multi-pass OCR,
  > извлекает по правилам/regex ключевые поля (наименование, код документа,
  > серийники, даты, производитель, гарантия и т.п.), при необходимости
  > доскан использует локальную мультимодальную LLM. Оценивает качество
  > извлечения, ведёт реестр между перезапусками и экспортирует данные в
  > Excel и 1С-совместимый JSON.

## 2. Структура проекта

```
project/
├── app/                       # Flask backend (исторически монолитный)
│   ├── app.py                 # вся серверная логика: OCR/Rules/LLM/API/Excel/Eval
│   └── templates/index.html   # single-page UI
├── src/                       # Логические слои (тонкие обёртки над app/app.py)
│   ├── data/                  # рендер PDF → изображения + embedded text
│   ├── ocr/                   # Tesseract multi-pass + предобработка
│   ├── rules/                 # baseline: regex/правила, нормализация
│   ├── llm/                   # improved: Ollama (доскан мультимодальной моделью)
│   ├── service/               # реэкспорт Flask app + основной endpoint
│   └── eval/                  # оценка на контрольной выборке
├── notebooks/
│   ├── 01_eda.ipynb           # разведочный анализ корпуса PDF
│   └── 02_baselines.ipynb     # сравнение baseline vs improved по метрикам
├── configs/
│   └── default.yaml           # карта значений конфига (рантайм читает .env)
├── tests/                     # pytest: rules, API, eval
├── samples/
│   └── control_samples.json   # контрольная выборка для метрик качества
├── приложения/                # демо-PDF (открытые паспорта КЭАЗ/ТРЭИ/Текон)
├── data/                      # runtime state (registry, logs)
├── artifacts/                 # выгрузки Excel/JSON, скриншоты прогонов
├── infra/                     # Dockerfile + docker-compose (app + ollama)
├── scripts/                   # start/stop bat+sh
├── .env.example               # шаблон конфигурации (реальный .env не коммитим!)
├── requirements.txt
├── report.md                  # отчёт по проекту
└── self-checklist.md          # самопроверка
```

> **Замечание про монолит.** Часть чистых функций (нормализация серийников,
> парсинг дат, eval-компаратор + константы) физически вынесены в
> `src/rules/normalize.py`, `src/rules/dates.py`, `src/rules/_constants.py`,
> `src/eval/compare.py` — `app.py` их импортирует.
> Остальные слои (OCR-обвязка, LLM, Flask-роуты, реестр) пока живут в
> `app/app.py` и реэкспортируются через `src/` для удобства ноутбуков и
> тестов. Дальнейшее разнесение монолита — следующий шаг (см. `report.md` §8).

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10`
- Tesseract OCR с языковыми пакетами `rus+eng` (только для запуска без Docker)
- Опционально — Ollama (для LLM-этапа); если её нет, сервис работает в режиме
  OCR+правила.

### 3.2. Установка окружения (без Docker)

```bash
cd project

python -m venv .venv
# Windows
.\.venv\Scripts\Activate.ps1
# Linux/macOS
# source .venv/bin/activate

pip install --upgrade pip
pip install -r requirements.txt

# Конфигурация
copy .env.example .env       # Windows
# cp .env.example .env       # Linux/macOS
```

Если Tesseract в нестандартном месте — задай `TESSERACT_PATH` в `.env`.

## 4. Как запустить проект

### 4.1. Docker (рекомендуется)

```bash
cd project

# Windows
scripts\start.bat
# Linux/macOS
./scripts/start.sh
```

Скрипт поднимет `app` + `ollama` через `infra/docker-compose.yml`, при
необходимости подтянет нужную LLM-модель и сообщит URL.

Открыть UI: <http://localhost:5000>

Остановить:

```bash
# Windows
scripts\stop.bat
# Linux/macOS
./scripts/stop.sh
```

### 4.2. Локально без Docker

```bash
cd project
python app/app.py
```

UI: <http://localhost:5000>

### 4.3. Ключевые эндпойнты

| Метод   | Путь                       | Назначение                                                  |
|---------|----------------------------|--------------------------------------------------------------|
| `GET`   | `/`                        | UI приложения                                                |
| `GET`   | `/health`                  | Health-check (`{status: "ok", llm_enabled: ...}`)            |
| `GET`   | `/api/meta`                | Текущая конфигурация OCR/LLM                                 |
| `POST`  | `/api/extract`             | **Основное извлечение** (multipart, поле `file`)             |
| `POST`  | `/predict`                 | Алиас `/api/extract` (под требование курса)                  |
| `POST`  | `/api/preview`             | Превью страниц PDF                                           |
| `POST`  | `/api/parse_cabinet`       | Разбор перечня шкафа                                         |
| `GET`   | `/api/registry/load`       | Загрузка сохранённого реестра                                |
| `POST`  | `/api/registry/save`       | Сохранение реестра                                           |
| `POST`  | `/api/export/excel`        | Экспорт реестра в Excel                                      |
| `POST`  | `/api/export/1c_json`      | Экспорт 1С-ориентированного JSON + отчёт валидации           |
| `GET`   | `/api/evaluate/default`    | Контрольный прогон на `samples/control_samples.json`         |
| `POST`  | `/api/evaluate/control`    | Контрольный прогон по переданному набору                     |

Проверка health:

```bash
curl http://localhost:5000/health
```

## 7. Демонстрация на защите

1. Поднять сервис через `scripts/start.bat` (Docker, ≈ 1–2 минуты).
2. Открыть <http://localhost:5000>, показать UI.
3. Загрузить PDF из [`приложения/`](./приложения/) — например, «Приложение 2 …
   Паспорт с одним заводским номером.pdf» — и показать извлечённые поля,
   `quality_score`, чек-лист и evidence-источники.
4. Запустить контрольный прогон кнопкой **Контроль** в UI (или
   `curl 'http://localhost:5000/api/evaluate/default?fast=1'`) — показать
   accuracy на контрольной выборке.
5. Открыть [`notebooks/02_baselines.ipynb`](./notebooks/02_baselines.ipynb)
   и показать таблицу сравнения **baseline (только OCR+правила)** vs
   **improved (+ LLM)**.

## 8. Ограничения и дальнейшая работа

Текущие ограничения:

- Серверная логика — монолит в одном `app.py` (наследие хакатона); `src/` —
  только реэкспорт. Физическое разбиение на модули — отдельная задача.
- Очень шумные/нечитаемые сканы требуют ручной валидации.
- Документы нестандартного формата попадают в `unknown` и обрабатываются
  только частично.
- LLM-этап включается опционально; качество улучшения зависит от того, какая
  модель доступна в Ollama (`llama3.2-vision`, `moondream`, ...).

Планы развития:

- Полностью разнести `app.py` по модулям `src/<layer>/` (без обёрток).
- Расширить контрольную выборку и фиксировать прогоны (MLflow / простой
  JSON-журнал в `artifacts/`).
- Добавить интеграционный коннектор 1С (сейчас только готовится формат
  выгрузки).
- Доразвить агентный сценарий: ассистент, который не просто отдаёт JSON,
  а объясняет оператору, какие поля «рискованные» и почему.
