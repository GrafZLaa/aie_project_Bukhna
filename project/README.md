# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

[![tests](https://github.com/GrafZLaa/aie_project_Bukhna/actions/workflows/tests.yml/badge.svg)](https://github.com/GrafZLaa/aie_project_Bukhna/actions/workflows/tests.yml)

В этой папке находится итоговый мини-проект по курсу.
Проект демонстрирует применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и воспроизводимость.

---

## 1. Паспорт проекта

- **Название проекта:** `ПАСПОРТ.ЦИФ — извлечение данных из PDF паспортов оборудования`
- **Автор:** `Бухна Даниил Валентинович`
- **Группа:** `ИКБО-42-24`
- **Контакт:** `@Grafzilla`

Проект — сервис, который читает PDF-паспорта промышленного оборудования и достаёт из них ключевые поля (наименование, код документа, серийники, даты, производитель).
Внутри связка OCR (Tesseract) + правила/regex + опциональный мультимодальный LLM-доскан через локальную Ollama.
Результат — REST API и UI, по PDF возвращается JSON по фиксированной схеме, плюс выгрузка в Excel и в формате JSON для 1С.

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки перед сдачей.
- `SECURITY.md` – правила работы с секретами и данными.
- `app/` – Flask-backend и UI:
  - app.py
  - templates/index.html
- `src/` – основной код, разнесённый по слоям:
  - data/, ocr/, rules/, llm/, service/, eval/
- `notebooks/` – экспериментальные ноутбуки:
  - 01_eda.ipynb
  - 02_baselines.ipynb
- `samples/` – контрольная выборка с эталонами:
  - control_samples.json
- `приложения/` – демо PDF-паспорта (КЭАЗ, ТРЭИ, ТеконГруп).
- `data/` – runtime-реестр сервиса, появляется при работе.
- `experiments/runs/` – журнал прогонов (config + metrics).
- `artifacts/` – JSON-замеры, графики, скрипт plot_results.py.
- `configs/` – конфигурационные файлы:
  - default.yaml
- `infra/` – Dockerfile + docker-compose.yml.
- `scripts/` – start/stop bat и sh для Windows и Linux.
- `tests/` – pytest-тесты.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10`.
- Tesseract OCR с языковыми пакетами `rus+eng` (только если запускать локально без Docker).
- Опционально Ollama (для LLM-шага; без неё сервис работает в режиме OCR + правила).
- Docker Desktop, если запускать через docker-compose (так проще всего).

### 3.2. Установка окружения

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение
python -m venv .venv

# Активировать окружение:
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt

# Конфигурация
copy .env.example .env       # Windows
# cp .env.example .env        # Linux/macOS
```

## 4. Как запустить проект

### 4.1. Запуск сервиса через Docker (рекомендуется)

```bash
cd project
scripts\start.bat        # Windows
# ./scripts/start.sh      # Linux/macOS
```

Скрипт поднимет `app` и `ollama` через `infra/docker-compose.yml`, дождётся готовности и напечатает URL. Сервис поднимается на порту **5000**.

Остановить — `scripts\stop.bat` или `./scripts/stop.sh`.

### 4.2. Запуск сервиса локально без Docker

```bash
cd project
python app/app.py
```

Тогда Tesseract должен быть в системе (или путь к нему задан в `TESSERACT_PATH`), а Ollama запущена отдельно (либо `ENABLE_LLM=0`).

### 4.3. Эндпойнты

- `GET /` — UI приложения.
- `GET /health` — health-check (`{status, service, llm_enabled}`).
- `GET /api/meta` — текущая конфигурация OCR/LLM.
- `POST /predict` — извлечение полей из PDF (alias `/api/extract`), принимает multipart с полем `file`.
- `POST /api/preview` — превью страниц PDF.
- `POST /api/parse_cabinet` — разбор перечня шкафа.
- `GET /api/evaluate/default?fast=1` — прогон на контрольной выборке.
- `POST /api/export/excel` — выгрузка реестра в Excel.
- `POST /api/export/1c_json` — выгрузка JSON для 1С с валидацией.

Простая проверка:

```bash
curl http://localhost:5000/health
curl "http://localhost:5000/api/evaluate/default?fast=1"
```

### 4.4. Запуск тестов

```bash
cd project
pytest tests -v
```

## 7. Ограничения и дальнейшая работа

Текущие ограничения:

- Контрольная выборка маленькая (7 PDF, 20 проверок) — 100 % accuracy на ней оптимистична, на широком корпусе цифры точно будут другими.
- Часть серверной логики ещё живёт в `app/app.py` (чистые leaf-функции вынес, остальное — следующий шаг).
- Очень шумные/нечитаемые сканы требуют ручной проверки.
- Качество LLM-шага зависит от того, какая модель доступна в Ollama.

В дальнейшем можно:

- расширить контрольную выборку до сотен PDF разных производителей и честно перемерить метрики;
- полностью разнести `app/app.py` по модулям;
- подключить трекинг экспериментов (например, MLflow);
- сравнить несколько vision-LLM (`qwen2.5vl`, `moondream`, `internvl`);
- сделать полноценный коннектор к 1С (сейчас только формат выгрузки).
