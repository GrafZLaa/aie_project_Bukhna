# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

[![tests](https://github.com/GrafZLaa/aie_project_Bukhna/actions/workflows/tests.yml/badge.svg)](https://github.com/GrafZLaa/aie_project_Bukhna/actions/workflows/tests.yml)

В этой папке находится итоговый мини-проект по курсу.  
Проект должен демонстрировать применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и (по возможности) воспроизводимость.

---

## 1. Паспорт проекта

- **Название проекта:** `ПАСПОРТ.ЦИФ — извлечение данных из PDF паспортов оборудования`
- **Автор:** `Бухна Даниил Валентинович`
- **Группа:** `ИКБО-42-24`
- **Контакт:** `@Grafzilla`

Проект посвящён построению сервиса автономного извлечения значимых данных из PDF/сканов паспортов промышленного оборудования.
Используется связка OCR (Tesseract) + regex/правила + опциональная мультимодальная LLM (Ollama, `llama3.2-vision`).
Результат — REST API + UI, который по входному PDF возвращает структурированный JSON по ключевым полям и формирует Excel-выгрузку для загрузки в учётные системы (1С).

---

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` — зависимости проекта.
- `report.md` — отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` — чеклист самопроверки проекта перед сдачей.
- `notebooks/` — экспериментальные ноутбуки:
  - `01_eda.ipynb`,
  - `02_baselines.ipynb`.
- `app/` — Flask-backend и frontend (single-page UI):
  - `app.py`,
  - `templates/index.html`.
- `src/` — логические слои пайплайна:
  - `data/`, `ocr/`, `rules/`, `llm/`, `service/`, `eval/`.
- `data/` — runtime-данные (реестр, логи); демонстрационные PDF — в `приложения/`.
- `configs/`:
  - `default.yaml` — карта параметров пайплайна.
- `samples/`:
  - `control_samples.json` — контрольная выборка с эталонами для метрик.
- `tests/` — pytest-тесты (`test_rules.py`, `test_api.py`, `test_eval.py`).
- `infra/` — `Dockerfile` + `docker-compose.yml` (app + ollama).
- `scripts/` — start/stop скрипты для Windows и Linux/macOS.
- `artifacts/` — выгрузки Excel/JSON, дампы метрик, скриншоты прогонов.
- `приложения/` — открытые PDF-паспорта (КЭАЗ, ТРЭИ, ТеконГруп) для демо и контрольного прогона.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10`.
- Tesseract OCR с языковыми пакетами `rus+eng` (только для запуска без Docker).
- Опционально — Ollama (для LLM-этапа); если её нет, сервис работает в режиме OCR+правила.
- Docker Desktop — для запуска через docker-compose (рекомендуется).

### 3.2. Установка окружения

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение (опционально, но рекомендуется)
python -m venv .venv

# Активировать окружение:
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt

# Конфигурация
copy .env.example .env       # Windows
# cp .env.example .env       # Linux/macOS
```

## 4. Как запустить проект

### 4.1. Запуск сервиса через Docker (рекомендуется)

```bash
cd project

# Windows
scripts\start.bat
# Linux/macOS
./scripts/start.sh
```

Скрипт поднимет `app` + `ollama` через `infra/docker-compose.yml` и сообщит URL.

### 4.2. Запуск сервиса локально (без Docker)

```bash
cd project
python app/app.py
```

UI: <http://localhost:5000>

### 4.3. Эндпойнты

- Сервис поднимается на порту **5000**.
- Ключевые эндпойнты:
  - `GET /` — UI приложения.
  - `GET /health` — health-check.
  - `POST /predict` — извлечение полей из PDF (alias `/api/extract`).
  - `GET /api/evaluate/default?fast=1` — контрольный прогон на `samples/control_samples.json`.
  - `POST /api/export/excel` — экспорт реестра в Excel.

Проверка работоспособности:

```bash
curl http://localhost:5000/health
curl "http://localhost:5000/api/evaluate/default?fast=1"
```

### 4.4. Тесты

```bash
cd project
pytest tests -v
```

## 7. Ограничения и дальнейшая работа

Текущие ограничения:

- Контрольная выборка маленькая (7 PDF), 100 % accuracy — оптимистичная оценка.
- Серверная логика частично остаётся в `app/app.py` (чистые leaf-функции вынесены в `src/`, остальное — следующий шаг рефакторинга).
- Очень шумные/нечитаемые сканы требуют ручной валидации.
- Качество LLM-этапа зависит от того, какая модель доступна в Ollama.

В дальнейшем можно:

- расширить контрольную выборку до 100-300 PDF разнообразных производителей;
- полностью разнести `app/app.py` по модулям `src/<layer>/`;
- подключить трекинг экспериментов (MLflow);
- сравнить несколько vision-LLM (`qwen2.5vl`, `moondream`, `internvl`);
- добавить полноценный коннектор к 1С (сейчас только подготовлен формат выгрузки).
