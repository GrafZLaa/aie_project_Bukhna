# Безопасность

Правила работы с секретами и данными в этом проекте.

## Секреты

Облачных API-ключей в проекте нет — LLM работает локально через Ollama, OCR и парсинг тоже оффлайн. Так что риск утечки минимальный, но дисциплину держу:

- настоящий `.env` (значения для конкретного запуска) в репозиторий не кладу;
- лежит только шаблон `.env.example` без секретов;
- `.env` исключён в `.gitignore` (и в локальном проектном, и в корневом).

Если кто-то когда-то добавит интеграцию с внешним сервисом (Telegram-бот, S3 для бэкапов реестра и т.п.), все токены — тоже только через переменные окружения.

## Данные

Что лежит в репо:

- `приложения/` — открытые PDF-паспорта оборудования (КЭАЗ, ТРЭИ, ТеконГруп), материалы хакатона. Никаких персональных данных.
- `samples/control_samples.json` — эталоны для контроля.

Что не должно попадать в репо:

- Реальные паспорта с заказчика, если они под NDA.
- `data/registry_state.json` — runtime-реестр сервиса. В нём могут быть base64-страницы загруженных пользователем документов. В `.gitignore`.
- `data/feedback_log.jsonl` — журнал отзывов через `/api/feedback`. Тоже в `.gitignore`.

Если хочется прогнать сервис на чувствительных документах — делать это локально и не пушить результаты. В `artifacts/` можно класть выгрузки прогонов, только если в них нет реальных серийников и контактов.

## API

Сервис принимает PDF или картинку. Остальные файлы парсятся PyMuPDF / Pillow как поток байтов — они изолируют разбор. Размер upload-а ограничен (`REGISTRY_B64_MAX`).

На ошибках возвращаю короткий JSON `{"error": "..."}` со статусом 400 или 500. Stacktrace наружу не отдаю. `/api/feedback` просто пишет тело в файл — никаких exec/eval.

LLM-шаг получает на вход OCR-текст из пользовательского PDF. Теоретически туда может быть встроена prompt-injection («отвечай как другой ИИ»). Чтобы это не ломало логику:

- системный промпт фиксированный (`PROMPT_EXTRACT` в `app/app.py`), требует ответ строго в JSON по схеме;
- ответ модели проходит через `clean_json()` и `_is_llm_payload_suspicious()` — подозрительное отсекается;
- на любом нестандартном поведении LLM откатываюсь на baseline (OCR + правила).

## Зависимости

Все пакеты из стандартного PyPI, перечислены в `requirements.txt`. В Docker-образе ставится только то, что в requirements, плюс системные пакеты для Tesseract и OpenCV. Веса `llama3.2-vision` тянутся через `ollama pull` в Docker-volume из официального registry Ollama.

## Чек перед сдачей

- В репо только `.env.example`, реального `.env` нет.
- Нет токенов, паролей, ключей.
- PDF в `приложения/` — открытые, не NDA.
- Runtime-файлы сервиса в `.gitignore`.
- `/health` отдаёт минимальный статус, без внутренних деталей.
- Ошибки API — короткий JSON, не stacktrace.
- LLM локальная, нет облачных ключей.

## Если что-то утекло

Удалить из текущей версии (`git rm`), закоммитить. Если файл уже запушен — считать его опубликованным, даже если потом удалить. Если утёк реальный токен — перевыпустить (отозвать) сразу, прятать смысла нет.
