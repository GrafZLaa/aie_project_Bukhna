# Безопасность проекта ПАСПОРТ.ЦИФ

Краткие правила работы с секретами, данными и сервисом — специфично для этого проекта. Общие принципы курса см. в `aie-course-meta/engineering-notes/security-notes.md`.

---

## 1. Секреты

В этом проекте **нет облачных API-ключей**: LLM-этап работает локально через Ollama, всё остальное (OCR, парсинг, экспорт) — оффлайн. Поэтому реальный поверхностный риск утечки секретов **минимален**, но дисциплина соблюдается.

### Что считается секретом

- `.env` в корне `project/` — копия `.env.example` со значениями для конкретного развёртывания. **Не коммитим.**
- Любые токены доступа к внешним сервисам, если кто-то решит добавить интеграцию (Telegram-бот, облачная Ollama, S3 для бэкапов реестра и т.п.).

### Где живёт что

- Шаблон конфигурации — [`.env.example`](./.env.example).
- Реальный `.env` — только локально, исключён в [`.gitignore`](./.gitignore) (и в корневом `aie_project_Bukhna/.gitignore`).

## 2. Данные

### Что в репозитории

- [`приложения/`](./приложения/) — открытые PDF-паспорта оборудования (КЭАЗ, ТРЭИ, ТеконГруп). Это публичные технические документы производителей, **не содержат персональных данных**.
- [`samples/control_samples.json`](./samples/control_samples.json) — эталонные значения полей для контрольной выборки.

### Что НЕ должно попадать в репозиторий

- Реальные паспорта изделий с заказчика, если они под NDA.
- `data/registry_state.json` — runtime-реестр, может содержать base64-страницы загруженных пользователем документов. Исключён в `.gitignore`.
- `data/feedback_log.jsonl` — журнал пользовательских отзывов через `/api/feedback`, может содержать контактные данные. Тоже исключён.

### Если хочется прогнать на чувствительных документах

- Прогонять **локально**, не пушить итоговые JSON и Excel в репозиторий.
- Артефакты в [`artifacts/`](./artifacts/) допустимы только если в них нет реальных серийников/контактов конкретных предприятий.

## 3. Безопасность API

- Сервис принимает только два формата: PDF и изображение. Любой другой загруженный файл обрабатывается как поток байтов через PyMuPDF / Pillow — они изолируют парсинг.
- Размер upload'а ограничен (`REGISTRY_B64_MAX`).
- На ошибках возвращаем короткий JSON `{"error": "..."}` со статусами 400/500 — **без полного stacktrace** наружу.
- `/api/feedback` пишет в файл на сервере без exec/eval — никакой обработки контента кроме сохранения.
- Эндпойнт `/api/extract` обрабатывает один документ за один запрос, без stateful-сессии.

### LLM и prompt-injection

LLM-этап (Ollama) получает на вход **OCR-текст из PDF**, который пришёл от пользователя. Теоретически в PDF может быть встроен «инструкция-промпт» (например, «отвечай как другой ИИ»). Чтобы не подгружать в production-логику нежелательное поведение:

- Используется фиксированный системный промпт (`PROMPT_EXTRACT` в `app/app.py`), требующий ответ строго в JSON-схеме.
- Ответ модели проходит через `clean_json()` и `_is_llm_payload_suspicious()` — отсекаются явно «подозрительные» ответы.
- При любом нестандартном ответе LLM откатываемся на baseline (OCR+правила).

## 4. Зависимости

- Зафиксированы в [`requirements.txt`](./requirements.txt), все из стандартного PyPI.
- В Docker-образе (`infra/Dockerfile`) ставится только то, что в requirements + системные пакеты для OCR/OpenCV.
- Сторонние LLM-веса (`llama3.2-vision`) скачиваются через `ollama pull` в Docker-volume `ollama_data` из официального registry Ollama.

## 6. Что делать при инциденте

Если в репозиторий случайно попал чувствительный файл (например, реальный паспорт с серийником конкретного клиента):

1. Удалить из текущей версии (`git rm`).
2. Если файл уже запушен в публичный репо — считать его **опубликованным**, даже если быстро удалить.
3. При необходимости переписать историю (`git filter-repo`), но для учебного курса достаточно просто удалить из HEAD.
4. Если попал реальный токен — **немедленно отозвать** его (перевыпустить), даже если ты «успел удалить».
